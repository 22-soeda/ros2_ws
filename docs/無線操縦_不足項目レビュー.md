## 1. 今できること

前後左右の平行移動（斜め可）、しゃがみ、右パンチ、左パンチ（腕だけ）、
起き上がり前・後、脱力、ホーム復帰、無線疎通確認。

デッドマン・加速度制限・無通信ウォッチドッグ・再武装といった安全側の作りは
すでに一通り揃っている。不足しているのは主に「戦うための動作そのもの」と、
「割り当てと実体の対応」である。

## 3. 整合性の穴 — なぜ (1) が見逃されたか

ここが今回いちばん効く指摘。

### 3.1 技名を突き合わせる仕組みがどこにも無い

- テストは `test_teleop.py` に34件あるが、すべて `roboone_teleop` パッケージ内で閉じている。
  パッケージを跨いだ照合が一つもない
- motion ノードは起動時に照合しない。「知らない技」の警告は
  `/cmd_motion` を受けた瞬間に初めて出る（`motion_node.cpp` の `handleMotionRequest`）
- したがって **試合中にボタンを押すまで分からない**

`motions.yaml` の冒頭には「定義していない技名を押しても警告が出るだけで何も起きない。
だから1本ずつ作っていける」と、この挙動を設計として肯定するコメントがある。
開発中は確かに便利だが、その代償として
**「割り当て済み ≠ 動く」が黙って成立する状態**ができた。

対策は軽い。どちらか一方でよい。

- motion ノードの起動時に、teleop config の `motion_bindings` に載っている技名が
  すべて `motions.yaml` にあるかを1回だけ調べて WARN を出す
- `motions.yaml` と `ps5_dualsense.yaml` を突き合わせるテストを1本足す

### 3.2 効かない経路にテストが付いている

`test_yaw_comes_only_from_right_stick` は「右スティックから `angular.z` が出る」ことを
検証しているが、motion ノードは `angular.z` を捨てる。
**効かない経路にテストがあり、効くべき経路（旋回）にテストが無い。**

このテスト自体は teleop の責務としては正しい（`/cmd_walk` の中身の検証）。
問題は、旋回が成立していないことをどのテストも捉えられないこと。

## 4. ミニマム4動作に対して決定的に足りないもの

### 4.1 旋回モーションの実体 — punch のコピペでは作れない

`motions.yaml` に2ブロック足すだけの作業に見えるが、そうではない。

`punch_r` は「腰を回す」を **足裏を Σ\_B の中で −ψ 回す**として実装している。
この式は足が床に固定されている前提で、両足とも固定なら閉ループになり胴は回れない。
実際には足裏が床を擦って部分的に回っているだけである。
パンチの一瞬なら成立するが、**旋回として使うと機体は回らずに脚がねじれるだけ**になる。

その場旋回をキーフレームで作るには、片足を浮かせて股ヨーで捻って下ろす、
つまり遊脚を含む動作が要る。歩行に近い難度になる。

未決の設計判断が2つ。

- **1回押して何度回るか。** キーフレームは離散イベントなので、押した回数で角度が決まる。
  刻みが粗いと相手に正対できず、細かいと回りきるのに時間がかかる
- **歩行と旋回は排他になる。** 技を撃つと `motion_node.cpp` の `handleMotionRequest` で
  `walk_.reset()` が走るため、旋回のたびに歩行状態がリセットされる。
  運用は「歩く → 止まる → 回る → 歩く」になる

### 4.2 起き上がりの腕の値が未取得

`motions.yaml` の `getup_front` / `getup_back` の節に、腕の値は仮であること、
「どちらへ振ると地面を押せるかは機体を寝かせてみないと決まらない」ことが明記されている。

脚のキーフレームは `leg_service` で補間点まで検算済みだが、
地面を押す腕が未検証なので**起き上がれる保証がない**。
規則 10.3(b) で3ダウンKOなので、起き上がれないと即敗退になる。

道具は既にある。

```bash
ros2 run roboone_motion_node motion_teach --out ~/draft.yaml
```

機体を寝かせて手で構え、捕まえた `arms:` の行を貼り替えるだけ。

### 4.3 脱力状態から起き上がる経路が壊れている

記録に無かった問題。

転倒すると、電波の瞬断（`joy_timeout` 0.5秒）か L1 で RELAX に入る。
RELAX から復帰する唯一の手段は Options 長押し、すなわち
`/cmd_motion "home"` → 0.1秒後に `/estop false` の2段送信である。
ここで motion ノードは次のように動く。

1. RELAX 中は `cur_pose_` に**実測姿勢**を毎周期入れ続けている。ここは正しい
2. 武装時、実測姿勢から `hold_pose_` へ `torque_on_time_` = **2.0秒**かけて補間する
3. `hold_pose_` は home、すなわち**立位姿勢**

つまり **寝ている機体で、脚を立位まで2秒かけて伸ばす**ことになる。
脚が床を押して機体が跳ねる。そこから改めて起き上がりを撃つ形になる。

さらに RELAX 中は `home` 以外の技をすべて弾くので、
**「寝たまま武装して、そのまま起き上がりを再生する」経路が存在しない。**

直しは小さい。**「今の実測姿勢のままトルクを入れる」武装ボタン**を1つ足せばよい。
`hold_pose_` に実測姿勢を入れて ARMING に入れば補間距離がゼロになり、
その場で固まるだけになる。そこから △ / ✕ を押せば、
寝た姿勢を起点に起き上がりが再生される。

既存の「実測位置を読む → それを目標として書く → トルクを入れる」という
3段のトルクオン手順がそのまま使えるので、新しい危険は増えない。

## 5. ミニマムでは切り捨ててよいもの

戦うために欲しいが、上の3つより後でよいと判断したもの。判断の根拠も残す。

| 項目 | 後回しでよい理由 |
|---|---|
| 攻撃技のレパートリー（蹴り・押し・投げ） | `punch_r` が1本通れば試合形式は成立する |
| `punch_l` の腰回転 | 右 ID2 の上限が原点から 0.5° しかなく、EEPROM を書き換える実機作業が要る。腕だけの左パンチで当面しのぐ |
| 防御姿勢・ガード | 「押している間その姿勢を保持する」という仕組み自体が今は無い。作るなら再生機構の拡張になる |
| 腕の直接操作 | 同上 |
| 転倒検知（IMU フィルタ） | 無線操縦なら操縦者が目で見て起き上がりを押せる。自律では必須 |
| 推定 ξ の踏み出し補正 | 押されたら倒れるが、起き上がれれば試合は続く。walk_core 側に差し込み口は用意済み |
| 電圧・温度の操縦者への表示 | `/motion/diagnostics` に出ているが誰も購読していない。試合前に確認すれば当面しのげる |
| 無線経路の冗長化 | Bluetooth 直結1系統。会場の電波状況を見てから考える |

## 6. 直す順番

1. **`turn_l` / `turn_r` を実際に作る。** `motion_teach` で片足浮かせ → 捻り → 接地を捕まえる。
   punch の「足裏を回す」式は流用できない（§4.1）
2. **起き上がりの腕を `motion_teach` で取り直す。** 機体を寝かせて捕まえるだけ
3. **「その場保持で武装」ボタンを足す。** 転倒 → 脱力 → 起き上がりの経路を通す（§4.3）
4. **b12 / b13 / b14 を `joy_probe` で照合。** 1〜3 を実機で試すついでに済む
5. **技名の照合を仕組みにする。** §3.1。(1) を二度と見逃さないための配線
6. **README の旋回3箇所と化石コメントを直す。** §2.2 (3)

1〜3 が終われば「歩いて、回って、殴って、起き上がる」が一周する。

現時点の正確な位置づけは、**4動作のうち完全に欠けているのは旋回だけで、
残る3つは「動くはずだが裏が取れていない」段階**である。

### 3 の注意

C++ 側 (`motion_node.cpp`) は手元に ROS が無くコンパイル未確認。Pi で
`colcon build --packages-select roboone_motion_node` を通してから、**`allow_torque:=false`** で
`hold` → `ARMING` → `STAY` の遷移と、`STAY` 中の `/motion/joint_commands` ≒ `/joint_states` を確かめること。
寝た姿勢が IK の到達域の外だと、実測姿勢を IK で往復した目標がクランプされて武装の瞬間にその軸が跳ねる。
これは既存の武装 (ホームへの補間の起点) と同じ性質だが、寝た姿勢で初めて効いてくる。
跳ねる軸があるなら、実測のサーボ生カウントをそのまま目標に書く経路 (IK を通さない) が要る。

`tools/` に ament と同じ規約の lint と、最小の rclpy 代替 (`tools/fakeros`) で teleop の結線テストを回す道具を置いた。
teleop の変更はそれで通してある (lint OK、テスト全件)。詳細は `tools/README.md`。
