# 相手機の認識: 練習会の録画 bag_0712 を検出器に通した結果

2026-07-12 の練習会で、本番と同じ大きさのフィールドを RealSense で録った `bag_0712/` を、
実機と同じ検出器（`RingDetector`、`opponent_detector.yaml` の値）に流して見た記録。
道具は `opponent_bag_viewer`（2026-09-24 作成。使い方は `docs/commands.md`
「realsense-viewer の録画（.bag）を検出器に通して見る」）。

**ここで言う OK 率は「何かを相手として出した割合」で、正しく出した割合ではない**
（正解ラベルが無いのは `src/roboone_perception/README.md` の「まだ確かめていないこと」の
とおり）。塊が正しいかどうかは、ビューアで画素ごとの塊と color 画像を並べて目で見ること。

## 1. bag の形式

- **realsense-viewer の録画で、ROS1 bag（`#ROSBAG V2.0`）。** `ros2 bag` では読めず、
  この Pi には rosbag（ROS1）も pyrealsense2 も無い。`roboone_perception/rsbag.py` が
  形式を直接読む（chunk は無圧縮）。
- depth は mono16・深度単位 0.001 m。color は bgr8。
- IMU は `Accel_0` と `Gyro_0` の**別 topic**で、どちらも約 200 Hz。
- **IMU の軸は depth の光学座標（x右 y下 z前）そのまま**で、回転はかけなくてよい。
  30° 付けの静止で加速度 (0.37, −8.47, −4.96) m/s²・|a| = 9.82 → 俯角 30.4°。
  検出器の鉛直 u の規約（加速度の向き = 上）とそのまま合う。
- header の時刻は実時刻（2026-07-12）。IMU は depth より 0.1〜0.2 秒早く始まっている。

「取り付けの実測」は、先頭のフレームで IMU の加速度（無ければファイル名の俯角）を
手がかりに床の平面を RANSAC で取り、その法線と距離から出したもの。

- IMU がある 2 本で、**加速度の鉛直と床の平面の法線の差は 1.4〜2.4°**。平面あてはめの
  残差は 2.3 mm。IMU と床の平面の向きはよく合っている。
- 手持ちのカメラ高さは 0.34 m 前後で、機体の設定値（`body.cam_height` 0.365）に近い。

## 3. 分かったこと

### 3.1 256×144 のモードは検出器の検証に使えない

depth 256×144 は **fx = 645 の中央の切り出し**（水平 22°・垂直 13°）で、低解像度の
広角ではない。水平付け・高さ 0.365 m だと床は **3.3 m 先からしか写らない**。検出器の
面あてはめは水平 1.5 m 以内の点を使うので、原理的に通らない。

実際に `field_424_256_holizontal` は RING_LOST 52%・ATTITUDE_STALE 28% で、床の平面も
最初から取れなかった。**録り直すなら 256×144 は避ける**（480×270 か 640×480 / 848×480）。

### 3.2 リング面と場外の床の段差は 0.32〜0.33 m

床の高さのヒストグラムには、カメラ高さ 0.34 m のときに **0.34 と 0.66 の 2 つの山**が出る。
段差は 0.32〜0.33 m。検出器の高さの窓（`body.cam_height` ± `tune.hist_window` 0.25）は
この段差より狭いので、**窓の中心が合っていれば**場外の床を掴まない。

### 3.3 場外の床しか写らないフレームで、窓の端に別の面が入る

`field_640_640_holizontal` の **8 秒付近**で、検出器が実測高さ 0.586 m の面をリング面として
掴んでいた（正しくは 0.35 前後）。窓の上端（0.365 + 0.25 = 0.615）ぎりぎりの面で、
鉛直が少しずれた状態の場外の床か、別の水平面と見られる。そのあと ATTITUDE_STALE に落ちた。

`field_424_256_30deg_imu` の **33〜36 秒**も同じ系統で、場外の床（0.66 の山）しか
写っていない間に、面あてはめが鉛直から 72〜73° 外れた面を返し、門で弾かれ続けていた
（門は正しく働いている）。

**窓の幅 ±0.25 m は、段差 0.32 m に対して余裕が 7 cm しかない。** ビューアでこの時刻を
コマ送りして、何を掴んだかを確かめる価値がある。

### 3.4 相手機の高さの分類

| bag | 立っている相手の上端 | 倒れた相手の上端 |
|---|---|---|
| `field_640_640_30deg_imu` | 0.32 m（0.7〜1.1 m 先） | 0.22 m |
| `field_640_640_holizontal` | 0.32 m | 0.21 m |
| `field_424_256_30deg_imu` | 0.25〜0.35 m | — |

今の境界（`fallen_top_max` 0.25 / `robot_top_max` 0.60）で、立位は「立位」、倒れた相手は
「転倒」に分かれていた。ただし**倒れた相手 0.21〜0.22 m は境界 0.25 まで 3〜4 cm**しかない。

### 3.5 検出器の処理時間（Pi 5、bag の再生）

| depth | mean | p95 |
|---|---|---|
| 480×270 | 12〜14 ms | 21 ms |
| 640×480 | 22〜28 ms | 35〜44 ms |

640×480 の p95 は 30 Hz の予算 33 ms を超える。

### 3.6 状態の割合（参考）

| bag | OK | NO_OPPONENT | ATTITUDE_STALE | RING_LOST | 測り直し |
|---|---|---|---|---|---|
| `field_424_256_30deg_imu` | 83% | 11% | 6% | 0% | 4 回 |
| `field_640_640_30deg_imu`※ | 82% | 15% | 2% | 0% | 1 回 |
| `field_640_640_30deg`※ | 87% | 13% | 0% | 0% | 0 回 |
| `field_640_640_holizontal`※ | 74% | 13% | 12% | 0% | 5 回 |
| `field_424_256_holizontal` | 6% | 14% | 28% | 52% | 236 回 |

「測り直し」は、RING_LOST / ATTITUDE_STALE が 15 枚続いたときにビューアが取り付けを
測り直した回数。**実機の検出器には無い動き**なので、実機での割合はこれより悪くなりうる
（`--no-reacquire` で実機と同じ条件で流せる）。

## 4. ビューアの前提と限界

- **bag は手持ち（または三脚）で、機体の歩行の揺れは入っていない。** 歩行中の姿勢の
  追従は、この bag では確かめられない。
- IMU の無い bag はジャイロの予測が無く、床の平面だけで鉛直を追っている。
- 取り付けの測り直しでは、直前の高さから ±12 cm 以内の山だけを採る。最初は場外の床
  （0.66 m）を掴んでしまったので、そうしてある。
- シークすると、行き先の 0.5 秒手前から取り付けを測り直して流すので、続けて再生した
  ときと追尾や姿勢が少し違うことがある。

## 5. 次に見るところ

1. `field_640_640_holizontal` の 8 秒付近と `field_424_256_30deg_imu` の 33〜36 秒を
   ビューアでコマ送りして、高さの窓が何を掴んだか確かめる（3.3）
2. 転送が終わった 640×480 の bag を最後まで流し直す
3. 倒れた相手の上端（0.21〜0.22 m）と `fallen_top_max` 0.25 の余裕を、実機の相手機で確かめる（3.4）
4. 録り直すなら 256×144 を避け、IMU も一緒に録る（3.1）

```bash
ros2 run roboone_perception opponent_bag_viewer bag_0712/0712_field_640_640_holizontal.bag --start 7 --paused
ros2 run roboone_perception opponent_bag_viewer bag_0712/0712_field_424_256_30deg_imu.bag --start 32 --paused
ros2 run roboone_perception opponent_bag_viewer bag_0712/ --batch       # 表の数字の取り直し
```
