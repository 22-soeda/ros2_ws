# walk_core 仕様 — 歩行計画エンジン (平行移動・純フィードフォワード)

- 対象: ROBO-ONE Auto 2026 機。`docs/ros2_walk_implementation.pdf` (以下、実装ノート) の §3〜§5 を実装したもの
- 実装: Python (原本) `src/roboone_motion/roboone_motion/walk_core/`、C++ `src/roboone_walk_core/`、JS `src/roboone_motion/roboone_motion/viz/walkcore.js`
- 作成: 2026-08-28。実機接続前 (実装ノート §11 の手順 1〜2 まで)

## 1. 範囲と前提

| 項目 | 今回の仕様 | 実装ノートとの違い |
|---|---|---|
| 移動 | **平行移動のみ**。前進・後進・左右・斜め (vx, vy) | ωz ≡ 0、足ヨー ψ ≡ 0。式 (2)(3)(5)(17) の回転項は恒等 |
| 姿勢推定 | **なし** (IMU 外挿なし)。ξ は常に計画値 | 実装ノート §3.4 の「ξ の出どころ」スイッチの計画側だけ |
| 座標 | **世界座標** (初期立位の骨盤直下が原点、x 前・y 左・z 上) | 回転がないと式 (3) の乗り換えは純平行移動になり、世界座標での積分と厳密に等価 |
| 決定性 | 時計・乱数を持たず `update(vx, vy, dt)` の入力列だけで決まる | 実装ノート §1.3 どおり |
| 出力 | 足先目標 (世界座標 / 骨盤水平座標系 {L})、ξ・重心・ZMP、状態、1 歩のパラメータ | IK・サーボ変換は含まない (roboone_kinematics / feetech_servo の仕事) |

## 2. インターフェース

```
update(vx_cmd, vy_cmd, dt, estop=False) -> WalkOutputs   # 200 Hz で呼ぶ
reset()                                                   # 立位・原点へ (home 技相当)
```

`WalkOutputs` (全て世界座標 [m], [s]):

| フィールド | 意味 |
|---|---|
| `state` | IDLE / START / STEP / STOP / ESTOP |
| `step_idx`, `phase` | 歩番号、位相 φ = t_local/T (START では押し出し経過/上限) |
| `support` | +1 左足支持 / −1 右足支持 / 0 両足 |
| `v` | 整形後の指令 (vx, vy) |
| `xi`, `com`, `zmp` | DCM ξ、重心 x_C (水平)、ZMP 参照 p |
| `left_foot`, `right_foot` | 足裏中心 (x, y, z)。接地中は z=0、遊脚は軌道の高さ |
| `pelvis` | (x_C, z_c)。骨盤 = 重心の水平投影とみなす (r_PC = 0) |
| `p_nom`, `p_land`, `b_next`, `xi_eos`, `clamp_box` | 計画中の 1 歩のパラメータ (§4)。歩の外では None |
| `locked`, `stopping` | 着地点を凍結したか / 停止シーケンス中か |
| `foot_targets_pelvis()` | {L} での足先目標 (足 − 骨盤)。IK への入力 |

足の符号は **+1 = 左、−1 = 右** (y は左が正)。

## 4. アルゴリズム (毎周期)

番号は実装ノートの式番号。

1. **指令の整形** — 式 (1) の飽和 + レート制限。式 (2) の楕円制限は (vx, ωz) ではなく
   **(vx, vy)** に適用し、斜め歩きで遊脚到達域 (式 18) を超えないようにする
2. **1 歩のパラメータ** (支持足 p_i、次の足の側 s_{i+1} = −s_i)
   - 歩幅 L = v T (式 4)、名目着地点 p_nom = p_i + (Lx, s_{i+1} W + Ly) (式 5、Δψ=0)
   - DCM オフセット。着地変位 ℓ が 2 歩周期 (ℓ_A, ℓ_B) の定常解を成分ごとに
     `b = (ℓ_A e^{ωT} + ℓ_B)/(e^{2ωT} − 1)` で置く。
     ℓ_first = p_i→p_{i+1} = (Lx, s_{i+1}W+Ly)、ℓ_second = p_{i+1}→p_{i+2} = (Lx, s_iW+Ly) として
     **b_here (= b_i、START の遷移目標)** = (ℓ_first e^{ωT} + ℓ_second)/(e^{2ωT}−1)、
     **b_next (= b_{i+1}、式 10 用)** = (ℓ_second e^{ωT} + ℓ_first)/(e^{2ωT}−1)。
     前後では式 (6)、左右 (Ly=0) では式 (7) に一致し、横移動 (Ly≠0) では式 (8) より正確
   - 終端予測 ξ_eos = p_i + (ξ − p_i) e^{ω(T − t_local)} (式 9、計画値なので閉形式で厳密)
   - 着地点 p_land = p_nom + k_dcm (ξ_eos − (p_nom + b_next)) (式 10) をクランプ域 (式 11) に収める。
     クランプ域は p_nom まわりで前後 ±0.04、外側 +0.045、内側 −0.015 (内外は着地脚の側で決まる)
   - φ < φ_lock の間は毎周期更新、以後は凍結
3. **ξ と重心** — 式 (12)。ξ は歩の始点からの閉形式 `ξ = p + (ξ_ini − p) e^{ω t_local}`、
   重心はオイラー積分 `x_C += ω(ξ − x_C) dt`
4. **遊脚** — 式 (14)〜(16)。5 次多項式 s(τ)、xy は r_0 → p_land、z は τ<0.45 で上昇・以後
   下降 (突き抜け z_od、降下速度 td_speed_max で飽和)。ψ は常に 0

## 5. 状態機械

```
IDLE ──|v|≥v_start_eps──▶ START ──ξ_y が p_sup+b_here を越えた──▶ STEP ⟲ (歩の境界で支持脚交代)
  ▲                          │ 押し出し上限 or |v|<v_stop_eps                │ 境界で |v|<v_stop_eps
  │                          ▼                                              ▼
  └──|ξ−x_C|<settle_eps── STOP ◀──────────── prep 歩 → stop 歩 (足を揃える) ──┘
                            │ ξ が支持多角形の外 → もう 1 歩 (STEP)
ESTOP: 全状態から。凍結し、復帰は reset() のみ
```

- **IDLE**: ξ = x_C = ZMP = 両足の中点
- **START** (実装ノート §4.1): 最初の支持足を決め、**反対の足に ZMP を置いて** ξ を支持足の上へ押し出す。
  遷移目標は p_sup + b_here。横移動があるときは **進行方向側の足から踏み出す** (支持足はその反対)。
  既定 (前後のみ) は左支持・右足から
- **STEP** (§4.2): 境界で支持脚を交代し、ξ_ini = 現在の ξ、遊脚始点 = 床を離れる足の位置。
  境界は計画では位相 1.0 ちょうど (接地判定は実機で入れる)
- **STOP** (§4.3): 両足支持で ZMP を ξ (両足中心を結ぶ線分に射影) に置き、重心が ξ に収束したら IDLE

### 停止シーケンス (2 段)

停止を判断した歩では ξ_ini が既に歩行のオフセットを持ち、終端 ξ は変えられない
(ξ_eos は支持足と ξ_ini だけで決まる)。そこで:

1. **prep 歩**: 次の歩の始点オフセットが式 (21) の `b_{N−1} = (0, s_N W/2) e^{−ωT}` になるよう
   `p_land = ξ_eos − b_{N−1}` と置く (s_N = いまの支持足の側)
2. **stop 歩**: 名目は支持足の真横 p_N = p_{N−1} + (0, s_N W)。中点条件 m_N = ξ_eos を
   `p_N = 2 ξ_eos − p_{N−1}` と解いてクランプ (準備どおりなら名目に一致)
3. 着地後 STOP → IDLE

停止シーケンス中に指令が復活しても完了させる (途中復帰は ξ の整合が崩れて発散する)。
歩き直しは IDLE から START でやり直す。

## 6. 安定条件 (純フィードフォワード固有)

着地点の誤差は次の歩で **e^{ωT} ≈ 22.9 倍** に増幅される。式 (10) は 1 歩で誤差を吸収する
デッドビート則だが、クランプで吸収しきれない残差が出ると発散する。したがって:

- **1 歩あたりの指令変化** ΔL = a_max·T が吸収可能な範囲でなければならない
  `ΔLx (1 + 1/(e^{ωT}−1)) < step_clamp_x`、`ΔLy (1 + 1/(e^{ωT}+1)) < step_clamp_in`
  → a_x < 0.24, a_y < 0.09。余裕を持たせて **a_max = (0.15, 0.08)** にした
- **離散化誤差**も同じ増幅を受ける。START の ξ 交差 (5 ms で最大 3 mm の行き過ぎ) と歩の境界は
  閉形式で交差時刻 / T ちょうどを取り、ξ をその点に置く
- 推定 ξ を入れて踏み出し補正を有効にする段階 (実装ノート §9 段 7, 8) で、a_max を戻すか再検討する

## 8. 3 実装の同期ルール

Python が原本。ロジックを変えるときは **3 つ揃えて** `compare_walk_engines.py` を回す。
C++ 版は YAML を読まず、既定値を gait.yaml と同じにしてある (motion ノードが ROS パラメータから詰める)。
