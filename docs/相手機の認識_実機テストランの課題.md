# 相手機の認識 実機テストランの課題（2026-09-20）

`opponent_testrun.launch.py` を実機のカメラで初めて回したときに出た症状の記録。
**原因は確定していない。** ここに書くのは「画面から読めたこと」「コードから絞れる経路」
「まだ確かめていないこと」まで。設計は [相手機の認識.md](相手機の認識.md)。

## 観測 1: 立たせたのに「姿勢が劣化」から戻らない

`home:=true` でホーム姿勢まで立たせた直後（フレーム 199、起動から約 7 秒）。

| 画面 | 値 |
|---|---|
| 判定 | 姿勢が劣化（床の面あてはめが通らない）= `ATTITUDE_STALE` |
| motion | `HOLD`（ホーム姿勢で立ち終えている） |
| 周期 / 処理 | 28.8 Hz / 26.8 ms |
| 俯瞰図 | 赤（面より上・リングの外）がほぼ全面。灰色（見えたリング面）は正面の数セルだけ |
| 相手 | 0.72 m / 12.6°、上端 0.19 m、幅 0.10 m、速度 0.83 m/s、外挿中 |
| 立位高さ H_o | 0.69 m |

読み取れること:

- 床がほとんど取れていないので、緑の「相手 0.72 m」は**壁か家具の一部**。上端 0.19 m・
  幅 0.10 m・速度 0.83 m/s・外挿中 という値がそれを裏づける。H_o 0.69 m も、最初の
  2 秒に別の高い物で較正された値。
- 鉛直の推定が床の法線と 12°（補正の門）より大きく食い違い、**自力では戻れない状態**。

**対処済み。** この観測から「基準姿勢の取り直し」を実装した（[相手機の認識.md](相手機の認識.md)
§7 の項）。偽のカメラでは再現と復帰を確認したが、**実機でこの症状に対して効くかは未確認。**

立位高さ H_o の較正そのものも 2026-09-23 に無くなった。ここで見えている「最初の 2 秒に
別の高い物で較正された 0.69 m」がまさにその弱点で、いまは転倒・立位の境界をクラスタ
上端の絶対値で置いている（[相手機の認識.md](相手機の認識.md) §5）。この行の H_o は
当時の画面の記録として残してある。

## 観測 2: 最初は俯瞰図が出ていたのに、途中から「リング面が取れない」

観測 1 のあと、取り直しを入れた版で回したとき。**起動直後は俯瞰図に床が描かれていたが、
途中で消えてそのまま戻らなかった**（ユーザ報告）。消えたあとの画面:

| 画面 | 値 |
|---|---|
| 判定 | リング面が取れない = `RING_LOST` |
| 周期 / 処理 | 30.0 Hz / **6.3 ms** |
| フレーム | 3248（起動から約 108 秒） |
| 俯瞰図 | **1 セルも無い**（赤も灰色も無い） |
| 相手 | 全部 `-` |
| 立位高さ H_o | 0.51 m・較正「済」 |
| 深度画像 | 有効画素は豊富。右手前に近い物（暖色）、他は遠い（青）、黒い抜けあり |
| motion | 上部のトルクのバーが無い ＝ `home:=false` で起動（機体は脱力） |

### コードから絞れること

**止まっているのは高さヒストグラムの段**（`detect/ring.py` の `ring_height`）で、
`h_r` が `None` を返して早期に抜けている。根拠は 3 つ。

1. **処理 6.3 ms。** 観測 1 の 26.8 ms、合成シーンの 13〜16 ms と比べて極端に短い。
   `h_r is None` の早期 return は、逆投影 → 姿勢 → ヒストグラムまでしか走らない。
2. **俯瞰図が完全に空。** グリッドを作る段まで到達していれば、少なくとも赤（面より上）は
   描かれる。`ring_mask` が `None` のままなのはこの経路だけ。
3. **深度は来ていて有効画素もある。** 周期 30.0 Hz、深度画像にも点がある。
   点が 0 枚の経路ではない。

`ring_height` が `None` を返すのは、**高さ `-cam_height ± hist_window` の窓に入る点が
`hist_min_points` に満たないとき**だけ。今の設定では

```
cam_height = 0.40（★未実測の仮値）、hist_window = 0.25、hist_min_points = 300
→ 窓は カメラ原点から 0.15 m 下 〜 0.65 m 下
```

つまり **「カメラから 0.15〜0.65 m 下のところに、平らな面が 300 点ぶん見えていない」**
という状態。一度この状態に入ると面の引き戻しも効かないので、鉛直はジャイロ任せで
劣化し続ける（観測 1 と同じ袋小路に、別の段から入る）。

### 仮説（未確認。可能性の高い順）

1. **実際のカメラ高さが窓から外れた。** `home:=false` で機体は脱力していた。机や手の上で
   カメラが低い位置にあれば、床は 0.15 m より浅いところに写り、窓に入らない。
   「最初は見えていた」のは、たまたま床が窓に入る置き方だったから。置き方や持ち方が
   変わった時点で外れた、という筋書きと症状が合う。
   **この場合、基準姿勢の取り直しでは直らない**（直すのは鉛直であって `cam_height` ではない）。
2. **鉛直が先に外れて、高さの計算ごとずれた。** 観測 1 と同じ原因が先行し、その結果
   床が窓から出た。脱力状態で機体を動かせば起きうる。この場合は取り直しで直る。
3. **カメラが床を見ていない。** 深度画像の大半が遠方（青）で、右手前だけが近い。
   水平付けのカメラは床を `cam_height × 1.8` より遠くでしか捉えないので、向き次第では
   床が視野から外れる。

1 と 2 は画面の「カメラ高さ 実測」で切り分けられるが、**`RING_LOST` のときはその欄が
`-` になる**（`ring_height` が `None` だから）。今の画面では切り分けられない。

### 手順そのものの問題

テストランの案内（[commands.md](commands.md)）に書いた
**「まず脱力のまま、カメラだけで見る」は、この検出器では成立しない。**
高さヒストグラムの窓は「カメラが `cam_height` の高さにある」ことを前提にしていて、
幅は ±0.25 m しかない。脱力した姿勢（カメラが低い）とホーム姿勢（0.4 m 前後）は
この窓を跨ぐので、脱力のままでは床を掴めない。

実機で見るときは `home:=true` でホーム姿勢に立たせるか、カメラを `cam_height` と
同じ高さに置いて回すこと。案内を直す必要がある。

## 診断が足りないところ（画面に出ていない量）

原因を確定させるのに要るのに、今は見えない。

| 欲しい量 | 今どうなっているか |
|---|---|
| 高さの窓に入った点数 `n_win` | `ring_height` が返しているのに**捨てている**。`RING_LOST` の理由がこれで一発で分かる |
| 床が実際に何 m 下に見えているか | `RING_LOST` では「カメラ高さ 実測」が `-`。**窓の外に外れた床の高さ**を出せば仮説 1 と 2 を切り分けられる |
| 高さヒストグラムそのもの | 出ていない。峰が 2 つあるのか、窓の外にあるのか、そもそも平らな面が無いのかが分かる |
| `RING_LOST` の内訳 | 「窓に点が足りない」と「床は取れたが連結成分が空」が同じ表示になる |
| 鉛直と床の食い違い | `correct()` まで届かないので**古い値のまま止まる**。増えていないからといって正常ではない |

俯瞰図が空のとき、「深度が来ていない」のか「床が窓から外れた」のかも画面では区別しにくい
（周期の表示で読めるだけ）。

## 次にやること

1. **`cam_height` と `cam_offset_x/y` を実測して入れる。** 仮値 0.40 m のまま追い続けても
   切り分けられない。測るのは床から depth の光学中心（カメラ自身から見て左の IR レンズ）まで、
   ホーム姿勢で立たせた状態で。
2. **上の診断を画面に出す。** 少なくとも `n_win` と「窓の外に見えている面の高さ」。
3. **`home:=true` で立たせた状態で取り直しを押し、観測 1 が実機でも直るか確かめる。**
4. 直らなければ、深度と IMU を bag に録って机上で回す。
   `ros2 bag record /camera/depth/image_rect_raw /camera/depth/camera_info /camera/imu`
