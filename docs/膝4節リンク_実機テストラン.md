# 膝 4 節リンク 実機テストラン

膝を手で曲げて、そのモータ回転から 3D モデル（脚＋4 節リンク）がリアルタイムに
追従することを確かめる。**サーボの角度を読むだけで、トルクは入れない。**

| | |
|---|---|
| 目的 | 4 節リンクの変換 (KN-5) が実機の動きと合っているかを目で確かめる |
| 副産物 | サーボ原点 φ0 の原点出し、σ_m と枝 (β, ε) の確定 |
| 安全 | 書き込みは起動時のトルク OFF（脱力）1 回だけ。位置指令もトルク ON も出さない |

## 構成

```
膝サーボ ──(読むだけ)──▶ feetech_knee_stream ──JSON行──▶ serve_knee3d.py ──HTTP──▶ ブラウザ
   角度                    (C++/feetech_servo)          (4節リンク+脚IK)        (3D表示)
```

| ファイル | 役割 |
|---|---|
| `feetech_servo/test/feetech_knee_stream.cpp` | サーボ角を JSON 行で流す。書き込み経路を持たない |
| `roboone_motion/viz/serve_knee3d.py` | 生角 → θ2 → 4 節リンク → 曲げ量 → 脚の関節位置 |
| `roboone_motion/viz/knee3d.html` | 3D 表示（脚 + リンク）と読み値のパネル |

表示に使っているのは `scripts/knee_fourbar.py` と `scripts/leg_ik.py` で、どちらも
C++ 実装と 1e-12 rad 以下で一致することを `crosscheck_knee.py` / `crosscheck_cpp.py` で
確認済み。可視化のために書き直した別実装ではない。

## 手順

### 0. ビルド

```bash
colcon build --packages-select feetech_servo roboone_kinematics
```

### 1. 表示だけ先に確かめる（実機不要）

```bash
python3 src/roboone_motion/roboone_motion/viz/serve_knee3d.py --demo
```

曲げ量 0 → 120° → 0 を 8 秒周期で往復する模擬データが流れる。画面上部に
オレンジの `DEMO` 帯が出る。ここで 3D とパネルが動くことを先に見ておくと、
実機で動かないときに「表示側か実機側か」の切り分けが要らない。

### 2. サーボ電源とバスを確認

```bash
ls -l /dev/feetech_*                                  # udev の固定名（ttyACM は入れ替わる）
ros2 run feetech_servo feetech_scan_test --port /dev/feetech_right --id-max 12
```

* **電圧が 11〜12 V あること。** 低いと読み取りが間欠的に欠ける。
* 応答した ID の一覧から膝の ID を確かめる（ID 7 があるのが右半身）。

### 3. 脚を伸ばしてから起動する

**起動した瞬間の姿勢を「膝が伸び切った状態」として扱う。** 先に脚をまっすぐ
伸ばしてから起動する。

```bash
python3 src/roboone_motion/roboone_motion/viz/serve_knee3d.py --port /dev/feetech_right --id 4
```

出た URL をブラウザで開く。SSH 越しなら `ssh -L 8102:localhost:8102 <pi>`。

### 4. 膝を手で曲げる

トルクは切ってあるので手で動く。見るところは 4 つ。

1. **伸び切りで曲げ量 0 になっているか。** ずれていたら脚を伸ばし直して
   「ゼロ取り直し」を押す。
2. **曲げる向きと表示の向きが合っているか。** 逆に動くなら「σ_m 反転」。
3. **曲げ量の数字が実際の角度と合っているか。** 大きくずれるならギア比 n を疑う。
4. **リンクの形が実機と合っているか。** 4 節リンクの拡大図（右上）と実機を見比べる。
   形が違うなら「β 反転」「ε 反転」を試す。1 姿勢合えば全域で合う。

### 5. 確定した値を書き込む

画面の「原点」欄に `knee_config.py` に書く値が出る。

```
PHI0_DEG    = ...
SERVO_SIGN  = ...
GEAR        = 1.0
```

枝を変えた場合は `BETA` / `EPS` も。C++ 側は `knee_config.hpp` の同名の定数。
書き換えたら検算を通し直す。

```bash
python3 -m pytest scripts/test_knee_fourbar.py -q
./build/roboone_kinematics/knee_selftest
```

`test_sigma_is_unique` が σ_knee の一意性を見るので、**枝を変えたら σ_knee も
検算し直される**（θ4_zero と枝から一意に決まるため）。

## 画面の見かた

| 表示 | 意味 |
|---|---|
| 曲げ量 | 膝の曲げ量。伸展 0・屈曲 +。`leg_config` の JOINT_LIMIT[KNEE] と同じ量 |
| θ₂ / θ₃ / θ₄ | クランク角 / カプラ角 / ロッカー角 |
| 伝達比 | dθ₄/dθ₂。作動域では 1.87〜2.22（モータ 1° が膝 2° 前後） |
| 伝達角 γ | 40〜140° が設計の目安。外れると力が伝わりにくい |
| ループ残差 | 拘束 \|B−A\| = r₃ の残差。1e-12 mm 台なら正常 |
| 読み取り欠損 | 5% を超えると赤。電圧を疑う |

赤い帯が出る条件は 4 つ。ストリーマが落ちた / 4 節リンクが組めない範囲 /
死点 / 電圧が 9 V 未満。

**4 節リンクを脚のどこに描いているか。** リンクの取り付け向き（O₄→O₂ が大腿の
どちらを向くか）は寸法 r₁–r₄ からは決まらないので、表示では大腿の中心線上
（膝から股方向に r₁ = 20 mm）に置いている。**動き方は取り付け向きに依らず正しい**
——— 地節は大腿に、ロッカーは下腿に固定されているので、機構は大腿・下腿と一体で回る。

## うまくいかないとき

| 症状 | 見るところ |
|---|---|
| `/dev/feetech_right が開けない` | udev 規則（`hw/99-feetech.rules`）とケーブル |
| `ID N が応答しない` | `feetech_scan_test` で ID を確認。バスの左右が逆かも |
| 読み取り欠損が多い | サーボ電源の電圧。低電圧で間欠的に欠ける実機の癖がある |
| 曲げても数字が動かない | ID が膝ではない。または `--gear` が違う |
| 曲げる向きと逆に動く | 「σ_m 反転」 |
| リンクの形が実機と違う | 「β 反転」「ε 反転」 |
| `Unreachable` が出る | サーボが 4 節リンクの組める範囲の外。ゼロ取りがずれている疑い |

## 検証済みの範囲（2026-08-28 時点）

| 項目 | 状態 |
|---|---|
| ストリーマのシリアル経路（開く・ping・トルク OFF・50 Hz 読み） | **実機で確認**（左バス ID 5、20 Hz・2 秒・欠損 0） |
| 書き込み経路がトルク OFF 1 回だけであること | ソース確認済み（`enable_torque(id, false)` 以外に書き込み呼び出しなし） |
| 生角 → θ2 → 4 節リンク → 曲げ量 → 脚の関節位置 | demo モードで通し確認（曲げ量 0–120° を 0.02° 以内で再現） |
| 3D に埋め込んだリンク長 | r₁–r₄ が 20/45/35/20 mm ちょうど（丸め誤差のみ） |
| 操作系（ゼロ取り直し・σ_m/β/ε 反転・不正値の無視） | 確認済み |
| **膝サーボでの実走** | **未実施**。サーボ電源が 3.4 V（正常 11–12 V）で、右バスが未接続だったため |

最後の 1 行が残っている。サーボ電源を入れて右バスを繋いだら、手順 2 から実行する。
