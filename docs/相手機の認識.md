# 相手機の認識（depth だけで、位置・転倒・人との区別を出す）

作成 2026-09-20。`roboone_perception`（検出）と `roboone_behavior`（転倒判定）が
depth 画像 1 枚から何をどう決めているかをまとめる。アルゴリズムの実測の根拠は
技術ノート(4) `docs/opponent_detection.pdf`、出場までの段取りは
[相手検知_出場ミニマム実装計画.md](相手検知_出場ミニマム実装計画.md)。
本書は **「どの量を、どの順に、何と比べて決めるか」** の一覧で、実装と 1 対 1 に対応する。

## 1. 入力と出力

| | 内容 |
|---|---|
| 入力 | `/camera/depth/image_rect_raw`（16UC1）と `camera_info`。**color と点群トピックは使わない。** depth を内部パラメータで逆投影した点の集まりが、ここでいう点群 |
| 補助 | `/camera/imu` のジャイロ。フレーム間の姿勢の橋渡しだけ（絶対の傾きは毎フレーム床の法線から取る） |
| 前提 | カメラは胴体に**水平付け**（俯角 0）。自機はリングの上に立っている |
| 出力 | `/opponent`（位置・距離・方位・上端高さ・幅・状態）、`/ring_edge`（方位ごとの床の切れ目） |
| 転倒 | `/opponent` の上端高さと幅から**行動層**が決める（検出器は形だけを出し、判断しない） |

## 2. 全体の流れ

```
depth ─ 逆投影 ─ 鉛直 u で (高さ h, 前 u, 左 v) へ ─ 高さヒストグラムでリング面 h_r
                                                        │
        ┌───────────────────────────────────────────────┘
        ├ |h − h_r| < 30 mm の点 → 5 cm グリッド → 自機の前から続く連結成分 = 見えたリング面
        │        └ 見えたリング面 ∪ 自機の位置 の凸包 = 「リングの内側」
        └ 40 mm < h − h_r < 900 mm の点 → 「面より上」
                 ├ リングの内側にあるもの → 連結成分 = 塊（クラスタ）
                 │        └ 重心・上端・幅 → 幾何フィルタ → 外から差し込む塊を棄却
                 │                 → 最近接を相手に → α-β 追尾 → /opponent
                 └ リングの外にあるもの → 人・什器。塊との接続を見るのにだけ使う
```

## 3. リングの内側をどう決めるか

相手を探す範囲は**リングの内側だけ**に閉じる（制限を外すと桜木町の bag で候補の 49% が
場外、厚木では 100% が場外。技術ノート(4) §8.1）。

「内側」は次で決める:

1. 床の帯（`|h − h_r| < 30 mm`）のセルのうち、**自機の正面の種の窓から続く連結成分**を
   「見えたリング面」とする。最大の面ではなく、自分が乗っている面を選ぶ。
2. **見えたリング面と自機の位置 (0, 0) の凸包**を「リングの内側」とする。

2 は 2026-09-20 に足した。理由は 2 つある。

- **水平付けのカメラは足元が写らない。** 垂直画角の下端は俯角 29° なので、床は
  `cam_height / tan 29°`（高さ 0.40 m で 0.72 m）より遠くしか写らない。以前は
  「見えたリング面の 1 セル隣まで」しか候補にしなかったので、0.7 m より近い相手は
  足元の床が見えず、**丸ごと候補から落ちていた**。間合い（0.25 m）で見失う。
- **相手の影で床が欠ける。** 相手の背後は床が写らず、相手の天面や奥の面の点が候補から
  外れていた（重心が手前の縁に偏る）。

リングは八角形で凸、自機はその上に立っているので、「見えたリング面と自機を結んだ凸包」は
必ずリングの中に収まる。場外へはみ出さない。種の窓の距離も、この下端の角度と
`cam_height` から自動で置く（`tune.seed_auto`）。

**近い相手は床を左右に分断する。** 0.45 m 先の幅 25 cm の相手の影は 1 m 先で幅 0.67 m に
なり、種の窓（±0.25 m）を丸ごと隠す。見えている床は左右 2 つの成分に分かれ、片方だけを
リングにすると凸包が相手を覆わない。そこで、**面より上の物の背後 1.5 m までを「影」とし、
影と物のセルを通れば種の成分へ届く床の成分を足す**（`tune.shadow_bridge`）。

足してよいのは**純粋な床**の成分だけにしてある。リングの外に立つ人や什器の垂直な面は
リング面の高さを横切るので床の帯に数セルの点を落とすが、同じセルに必ず面より上か下の点も
持つ。そういうセルが半分を超える成分と、6 セル未満の成分は足さない（合成シーンで、
足すと凸包が場外の人まで伸びて人が相手の候補に入ることを確認した）。

## 4. 重心・上端・幅

リングの内側にある「面より上」の点を 5 cm グリッドで 4 近傍の連結成分に分け、成分ごとに

| 量 | 出し方 | 使い道 |
|---|---|---|
| 重心 (x, y) | 成分に属する**点の (u, v) の平均** | 距離 ρ と方位 β |
| 上端 `top_height` | 点の高さの最大 | 転倒判定、人の棄却 |
| 幅 `width` | u・v それぞれの広がりの大きい方 + 1 セル | 転倒判定、什器の棄却 |
| 点数・セル数 | そのまま | 雑音の棄却（点数の下限は距離の 2 乗で緩める） |

- 重心は**見えている面の点の平均**なので、真の重心よりカメラ側に胴の半分（5〜8 cm）寄る。
  距離に依らない系統誤差で、間合い `strike_range` を実測で決めれば吸収される。
- 幾何フィルタ: 上端 0.10〜0.70 m、幅 0.05〜0.80 m、距離 ≤ 3 m、セル数 ≥ 2。
  幅の上限は規則の表 2（3 kg 級の腕は軸から 30 cm）から、腕を広げた 0.8 m。
- 通ったもののうち**最近接**を相手とし、α-β 追尾で均す。ゲート 0.35 m を外れた観測は
  棄却して外挿、8 フレーム続いたら軌跡を捨てる。

## 5. 立っているか、倒れているか

行動層の `FallenDetector`（`roboone_behavior/behavior/tracking.py`）。

| 証拠 | 条件 | 備考 |
|---|---|---|
| 低い | `top < 0.5 · H_o` | H_o は開始直後 2 s の上端の中央値（相手ごとに背丈が違う） |
| 平たい | `top < 0.22 m` かつ `width > 1.3 · top` | **較正が要らない。** 再開時に近距離へ置かれて較正が取れないときの保険 |
| 横に広い | `width > H_o` かつ 立位の高さに達していない | 腕を広げて立つ相手（T ポーズ）を転倒にしないため、高さの条件を付けた |
| 立っている | `top > 0.75 · H_o` | |

- 「低い / 平たい / 横に広い」のどれかが **0.7 s** 続けば転倒、「立っている」が **0.5 s**
  続けば復帰。上下で閾値を分けてあるのはヒステリシス。
- **間合いの中**（ρ < strike_range + 0.2 m）では上端が視野で切れて低く出るので、
  「低い」だけでは転倒にせず「横に広い」を併せて要求する。復帰の判定は凍結する。
- 規則の「ダウン」は手を着いただけの状態も含むが、高さからは見えない。
  **判定するのは横倒しだけ。** レフリーのカウント中、相手は数秒は倒れたままなので
  0.7 s の継続条件で間に合う。

## 6. ロボットか、人（操縦士・レフリー・観客）か

3 段の門で落とす。

| 門 | 落とすもの | 根拠 |
|---|---|---|
| 1. リングの内側だけ | 床に立つ人、什器、隣のリングの機体 | 人はリングより低い床に立つので、体がリング面の高さと交わる位置はリングの外。規則: 周囲 30 cm は空ける、操縦者は 50 cm 以上離れる |
| 2. 上端 ≤ 0.70 m | リングの上に身を乗り出した人の胴 | 床から立つ人の頭はリング面から 1.2 m 以上 |
| 3. **外から差し込む塊を棄却** | レフリーの腕・手、しゃがんだ人の頭。上端が低く幅も小さいので 1・2 を通る | 下記 |

門 3（2026-09-20 追加）: リングの内側の塊が、**リングの外にある「面より上」のセル**と
つながっていれば、外から入ってきた物として捨てる。

- リングの縁から外へ `tune.intrude_band_cells`（既定 10 セル = 50 cm。操縦者が離れる
  距離）の帯の中で、面より上の点が `intrude_cell_points`（3 点）以上あるセルをたどる。
  点数の下限は、深度の段差に出る飛び画素を物に数えないため。
- そのうち **「確かにリングの外」** のセルだけを外の物として数える。確かに外とは、
  自機から見たその方位で**床が自分で終わっていて**（終わりに物が立っていない）、その先に
  あるセルのこと。床が物に隠されて終わった方位や、床が 1 画素も写っていない方位
  （足元の死角）は「分からない」であって外ではない。**視野の端に立つ相手や、間合いの中の
  相手を、外の物と取り違えないための区別**（`detect/polar.py`）。
- 内側の塊から 4 近傍でつながる外の物が `intrude_min_cells`（4 セル）以上あれば、
  その塊は**外から差し込んでいる**と判定して相手にしない。
- リングの上に立つ機体は足元がリングの中にあり、外へはつながらない。縁から体が
  はみ出している相手（リングアウト寸前）は 4 セル未満なら通る。
- 重心・上端・幅は内側の点だけで出したままなので、つながっていても位置は場外へ引かれない。

## 7. 状態（見えないことの区別）

| status | 意味 |
|---|---|
| `OK` | リング面も姿勢も正常で、相手が見えている |
| `NO_OPPONENT` | 正常だが、条件を通る塊が無い（視野に相手がいない） |
| `ATTITUDE_STALE` | 床の面あてはめが門を通らず、姿勢がジャイロ任せで劣化中 |
| `RING_LOST` | リング面自体が取れない（転倒直後、場外を向いている） |

### 基準姿勢の取り直し

鉛直 u は「ジャイロで運び、床の法線で毎フレーム引き戻す」で持っている。引き戻しには門が
あり、推定中の u と床の法線が **12° より大きく食い違うと補正しない**（什器を斜めに貫く
平面に姿勢ごと引きずられないため。技術ノート(4) §5.4）。この門のせいで、**u が一度
12° より外れると、正しい床の法線まで弾き続けて自力では戻れない。**

脱力した姿勢で起動してから立ち上がる間や、転倒のあとは床が見えず引き戻しが効かないので、
これは実際に起きる（2026-09-20 実機のテストランで発生。立ったあとも「姿勢が劣化」の
まま、床がほとんど取れなかった）。最初が脱力した姿勢なのは避けられないので、
**ホーム姿勢で静止して立っているときに、基準姿勢を取り直す**。

| きっかけ | 使いどころ |
|---|---|
| `/autonomy` が true になった瞬間 | **試合。**「はじめ」の時点で機体はホーム姿勢で立っている。何もしなくても取り直される（`reset_on_autonomy`） |
| `/detector/reset_attitude`（`std_msgs/Empty`） | 手で送る。起き上がりのあとなど |
| テストランの画面の「基準姿勢を取り直す」 | テストラン。`home:=true` のときは、立ち終えて motion が `HOLD` になった時点で自動でも走る |

取り直しは、直近 0.4 秒の加速度の平均から u を置き直し、追尾を捨てる。**静止していない
ときは置き直さない**（歩行中の加速度は傾きが p95 で 28° ずれる。技術ノート(4) §5.2）。
静止の条件は角速度の最大が 0.15 rad/s 未満、加速度の平均の大きさが重力 ±0.6 m/s²。
満たさなければ最大 5 秒待ち、だめなら諦めてログに理由を出す。IMU が来ていない構成では
取り付けから決まる鉛直（水平付けなら真上）へ戻す。

画面の「鉛直と床の食い違い」が 12° を超えて張り付き、「引き戻しなしの連続」が増え続けて
いたら、この状態である。

## 8. 確かめたこと・確かめていないこと

- **合成シーンで確認済み**（`test/test_detect.py`、`opponent_viewer --demo`。2026-09-20）:
  水平付けで種の窓が床の写り始めへ動く／0.40 m の相手を見失わない／凸包が場外へ
  はみ出さない／外から差し込む腕を棄却し、縁に立つ相手は落とさない。デモの筋書きでは
  横倒しから 1.0 s で「倒れている」、立て直して 0.9 s で復帰、接近は 0.40 m まで追尾。
  Pi 5 で 1 フレーム 13〜16 ms（848×480・stride 2）。
- **偽のカメラで確認済み**（2026-09-20）: 35° 傾いた加速度と床の見えない深度で起動し、
  そのあと立った深度に替えると、実機と同じく「姿勢が劣化」のまま戻らない。取り直すと
  1 フレームで `OK` に戻る。ボタン・トピック・`/autonomy` の 3 つとも。
- **実機で確認済み**（2026-09-20）: `home:=true` でホーム姿勢までゆっくり立つところ。
- **実機のカメラでは未確認。** 2026-09-20 に初めて回したが、2 回とも基準（鉛直・リング面）
  を失って戻らなかった。症状と絞り込みは
  [相手機の認識_実機テストランの課題.md](相手機の認識_実機テストランの課題.md)。
  **§9 の「まず脱力のまま見る」はこの検出器では成立しない**（高さの窓が ±0.25 m しかなく、
  脱力とホーム姿勢を跨げない）。`home:=true` で立たせてから見ること。

### 既知の限界

- **縁に立つ相手のすぐ後ろに人が密着している**と、門 3 が相手ごと落とす。
  リングは台状で人は床に立つので、5 cm セルで隙間なくつながることは稀とみている。
  起きたら `tune.intrude_min_cells` を上げるか 0（無効）にする。
- **手を着いただけのダウン**は見えない（§5）。
- 重心はカメラ側に寄る（§4）。
- 相手が 2 台以上見えるときは最近接を採るだけ。
- 会場の照明・フラッシュの影響は未測定。正解ラベルも無い（技術ノート(4) §12）。

## 9. テストラン（リアルタイムのビューア）

実機のカメラで検出器をそのまま回し、ブラウザで俯瞰図・深度・判定を見る。
**サーボには一切触れない**（motion ノードを上げない）。

```bash
# カメラごと起動。起動時に表示される URL を手元の PC のブラウザで開く（既定 8105 番）
ros2 launch roboone_perception opponent_testrun.launch.py camera:=true

# カメラが既に上がっているなら
ros2 launch roboone_perception opponent_testrun.launch.py

# 実機なしで画面と判定だけ確かめる（合成シーン。相手が歩く・倒れる・人が腕を差し込む）
ros2 run roboone_perception opponent_viewer --demo

# 1 フレームごとの判定を CSV に残す
ros2 launch roboone_perception opponent_testrun.launch.py camera:=true log:=/tmp/opp.csv
```

**立たせた状態で見る（★トルクが入る）。** カメラは胴体に付いているので、本番と同じ高さ・
向きで見るには機体をホーム姿勢で立たせる必要がある。`home:=true` を付けたときだけ、
この launch が motion ノードも上げ、脱力している今の姿勢から**ゆっくり**ホーム姿勢へ移る。

```bash
# 機体を支えてから。motion の起動を確かめて 3 秒後にトルクが入り、6 秒かけてホームへ
ros2 launch roboone_perception opponent_testrun.launch.py camera:=true home:=true

# もっとゆっくり / トルクを入れずに流れだけ確かめる
ros2 launch roboone_perception opponent_testrun.launch.py camera:=true home:=true home_time:=10.0
ros2 launch roboone_perception opponent_testrun.launch.py camera:=true home:=true allow_torque:=false
```

- 既定は `home:=false` で、motion ノードを上げず、`/estop` にも `/cmd_motion` にも
  publisher を作らない（サーボへ何も書かない）。
- 送る順は teleop の Options 長押しと同じ `home` → `/estop false`。ゆっくりにしているのは
  motion の `torque_on_time`（既定 2 s）と `home_move_time`（1.5 s）を `home_time` 秒
  （既定 6 s）に上書きしているから。
- **止め方**: 画面上部の「脱力」ボタン、または Ctrl-C（ビューアが `/estop true` を置き、
  motion も終了時に脱力する）。teleop は上がらないので**コントローラの脱力ボタンは効かない**。
  ビューアが落ちたら launch ごと畳む。
- **`roboone.launch.py` と同時に上げない。** motion ノードが 2 つになりサーボのバスを取り合う。

`roboone.launch.py` が既定（`imu:=true`）で上がっていると RealSense は IMU 専用で
掴まれていて、depth が出ない。**機体の launch を止めてから `camera:=true` で上げる**か、
機体を `roboone.launch.py camera:=true` で上げ直してから `camera` 無しのテストランを足す。

画面の見方:

| 場所 | 見るもの |
|---|---|
| 俯瞰図 | 灰 = 見えたリング面、濃い灰 = リングの内側（凸包）、緑 = 相手の候補、赤 = リングの外の物、桃 = 確かに外の物、黄の輪 = 相手に選んだ塊、青の点 = 床の切れ目、破線の枠 = 種の窓 |
| 判定 | 「立っている / 倒れている / 見えない」と、その根拠（低い・平たい・横に広い・立位の高さ）、転倒・復帰までの継続時間 |
| 塊ごとの判定 | 内側の塊を近い順に。相手にしなかった理由（高すぎる・広すぎる・外から差し込んでいる 等） |
| リング面と姿勢 | **「カメラ高さ 実測」が `body.cam_height` の答え合わせ**。床を見せて立たせれば読める。「鉛直と床の食い違い」が 12° を超えて張り付いていたら「基準姿勢を取り直す」（§7 の次の項） |

ビューアは `opponent_detector` ノードそのものに HTTP の口を付けたもので、`/opponent` と
`/ring_edge` も通常どおり publish する。転倒判定は行動層の `FallenDetector` を同じ
パラメータで回す。立位高さの較正は起動直後と、画面の「較正し直す」で走る。

確かめる順（床に置いた箱か、トルクを切った相手機で）:

1. 1 m 先に立てて置く → `OK`、距離と方位が実測と合う、判定が「立っている」
2. 横倒しにする → 0.7 s ほどで「倒れている」。立て直すと 0.5 s ほどで戻る
3. 0.3 m まで近づける → 見失わない（§3 の凸包が効いている）
4. 人が横に立つ・しゃがむ → 相手にならない（門 1・2）
5. 人がリング相当の面の外から腕を差し込む → 塊は出るが「外から」で棄却される（門 3）
6. 床の切れ目（台の縁）→ `/ring_edge` の線が縁に沿う

## 10. パラメータ

検出器 `roboone_perception/config/opponent_detector.yaml`、転倒判定
`roboone_behavior/config/behavior.yaml`。

| 名前 | 既定 | 意味 |
|---|---|---|
