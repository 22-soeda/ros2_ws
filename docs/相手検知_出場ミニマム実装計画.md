# 相手検知（depth のみ）で auto に出るためのミニマム実装計画

作成 2026-09-20。対象は「RealSense の depth だけで相手を認識し、ROBO-ONE auto の
試合を最後まで反則なく戦える最小の構成」。規則は第 44 回競技規則（2025-06-11）、
設計は技術ノート(3)『自律機の動作計画指針』・(4)『敵機検出プログラムの構成』に従う。
**新しいアルゴリズムは足さない。** 足りないのは検出器ではなく、その周りの 4 点である。

## 先に結論

1. **検出器 `opponent_detector` と行動層 `behavior` は既に実装済み**（2026-08-28）。
   合成シーンと PC 上の bag で検証してあり、Pi 5 でも 30 Hz に収まる（合成で 21 ms）。
   **実機のカメラで一度も回していない。** ここから始める。
2. 出場を止めている穴は検出ではなく次の 4 つ。優先順に
   - **旋回ができない。** motion は `/cmd_walk` の `angular.z` を捨てる
     （`motion_control.hpp` 冒頭）。teleop が参照する `turn_l` / `turn_r` は
     `motions.yaml` に**存在しない**。行動層の SEARCH は旋回指令しか出さないので、
     相手が視野外にいると機体は動かず、10 秒でスタンディング（規則 10.3(d)）。
   - **検出器の窓が今の取り付けと合っていない。** 検出器は俯角 30°・高さ 0.35 m を
     前提にしているが、現物は「胴体に水平付け」で、**水平のまま使うと決めた**。
     リングを掴む種の窓を水平前提に置き直し、高さ・オフセットを実測で入れる（§2.2）。
   - **転倒したら自分で起きられない。** motion に FALL 状態が無く、`getup_*` は
     teleop から手で出している。試合中はコントローラに触れられない（作動方法の項）。
   - **行動層の速度定数が今の歩行と合っていない。** behavior は v 0.15 m/s・ω 0.8 rad/s
     を前提に書かれているが、実機は静歩行の観察モード（1 歩 6.4 s、v_max 0.10/0.04）。
3. 「depth のみ」の解釈: **color と点群は使わない。カメラ内蔵 IMU は同じデバイスから
   出る値で、既に姿勢の橋渡しに使っている（ジャイロだけ・加速度は初期化のみ）。**
   ジャイロを外すのは 1 パラメータで可能にしておくが、既定は残す（§3）。

## 2. 出場に要る最小の構成と、埋める順

各段に「これができたら次へ」の受け入れ条件を置く。**実機を動かす段は必ず機体を支えて、
`allow_torque:=false` で通しを見てからトルクを入れる**（CLAUDE.md の約束）。

### 2.1 段 0: 検出器を実機のカメラで回す（コード変更なし・今日できる）

- カメラを胴体に付けたまま `opponent_detector.launch.py camera:=true` を上げ、
  `/detector/debug` を見る。ロボットは脱力でよい。
- 測って yaml に入れる: **カメラ原点の床からの高さ `body.cam_height`、俯角
  `body.cam_pitch_deg`、機体原点からのオフセット `cam_offset_x`**。
- `ros2 bag record /camera/depth/image_rect_raw /camera/depth/camera_info /camera/imu`
  を**別建てで**回して 1 本残す（`record_topics.yaml` は画像を録らない方針）。
  以後の机上検証はこの bag で回す。
- 受け入れ: 段ボール箱を 0.5 / 1.0 / 2.0 m に置き、`/opponent.range` が ±5 cm、
  `status` が OK で 30 Hz。`detector_bench --duration 30` で p95 < 33 ms
  （motion ノードを同時に上げた状態で）。

### 2.2 段 1: カメラは水平付けのまま。検出器の窓を水平前提に置き直す

**決定（2026-09-20）: カメラは胴体に水平付けのまま使う。** 俯角は付けない。
motion の `imu.mount_rpy_deg` も 0 のままでよい。

水平だと写り方が変わるので、検出器の「機体から決まる」値と、俯角 30° 前提で
置いてある種の窓を直す:

| 項目 | 今 | 水平での値 |
|---|---|---|
| `body.cam_pitch_deg` | 30 | **0** |
| `body.cam_height` | 0.35 | **実測**（§2.1。骨盤高さ 0.261 m + 骨盤からカメラ光学中心までの高さ） |
| `tune.seed_near` / `seed_far` | 0.15 / 0.70 | **床が写り始める距離から +0.6 m**。垂直画角 58° の下端は俯角 29° なので、床は `cam_height / tan 29°` より遠くしか写らない（h=0.40 m で 0.72 m）。今の窓のままだと種が常に空でリングを掴めない |

水平の代償として床の死角が広がる（h=0.40 m で約 0.7 m）。ただし相手の胴体（高さ 0.3 m
以上）は `(h − 0.3) / tan 29°` ≈ 0.2 m まで見えるので、**相手そのものの検出は間合いまで
続く**。消えるのは近距離の `/ring_edge`（床の切れ目）で、縁の判断は 0.7 m 先までの
`d_cliff` と行動層の余裕 `edge_margin` で持つ。

受け入れ: 立位で `/opponent.status` が OK になり、`position.z`（相手重心のリング面からの
高さ）が箱の実寸と合う。`/ring_edge` の正面ビンが、0.8 m 先に置いた台の縁で有限値になる。

### 2.3 段 2: 旋回を作る（motion の技 + behavior の出し方）

**方針: 歩行計画にヨーを足さない。** キーフレームモーション `turn_l` / `turn_r` を
`motion_teach` で作り、行動層は旋回を `/cmd_motion` で出す。既に技を出す経路
（`technique` / `motion_busy` の追跡）があるので、そこに乗せる。

- motion: `motions.yaml` に `turn_l` / `turn_r` を追加。1 回で回る角を実測して記録
  （目標 15〜30°）。teleop の十字左右は既に名前を参照しているので、そのまま動く。
- behavior: `core.py` の SEARCH と、APPROACH の方位合わせを変える。
  - SEARCH: `ω` を出す代わりに、最後に見た方位側の `turn_*` を `/cmd_motion` で出し、
    `motion_busy` が落ちるまで待つ。技と同じ排他（同時に 1 つ）。
  - APPROACH: `|β| > bearing_out` のときは前進を止めて `turn_*` 1 回、
    `|β| < bearing_in` なら直進。横移動 `v_y` で細かい方位は吸収しない（静歩行の横は
    0.04 m/s しかない）。
  - `robot.turn_motions: [turn_l, turn_r]`, `robot.turn_step_rad`（実測値。
    `/odom` が無い間はリング座標系の推定にこの角を積む）をパラメータに足す。
  - `w_max` は使われなくなるが、将来のヨー歩行のために残す。
- 受け入れ（behavior README の検証順 2）: 箱を視野外 90° に置いて `/autonomy` true →
  旋回して `|β| < 8°` で止まり、直進に移る。旋回 1 回ごとの `/behavior/state` に理由が残る。

### 2.4 段 3: 行動層の数を今の歩行に合わせる

- `robot.v_max` 0.15 → **0.10**、`robot.v_y_max` 0.08 → **0.04**（`static_gait.yaml` の
  v_max と同じ）。`robot.step_period` は静歩行の 1 歩の実測（今 6.4 s、本番向けに戻せば
  約 2.1 s）。
- **10 秒無移動の見張り**: 観察モードの 1 歩 6.4 s では、指令から実際に足が動くまで
  `t_shift_min 0.9 + t_swing 1.8` 秒かかる。`keepalive_period` 6 s のままだと、SEARCH
  中に旋回モーションを待っている間に 10 秒を超える恐れがある。旋回モーション自体を
  「移動」と数えるか、レフリーに確認する（規則は「前後左右に移動」と書く。旋回は
  移動に入らない読みが安全側）。**静歩行を本番の速さ（観察用の 1/3 を戻す）にすることが
  前提**で、これは歩行側の作業。
- `tune.k_range`, `tune.range_eps` は APPROACH の停止距離の分布を取ってから（検証順 3）。
- `robot.blind_range` を実測で置く（D435 の 848×480 は仕様上 0.28 m 前後）。
  `strike_range` 0.25 より死角が遠いなら、間合いの判定は「最後に見た距離 − 歩いた距離」
  の外挿になる。behavior の `tracker` は既にこれをやる（`_step_close`）。

### 2.5 段 4: 転倒の検知と自律起き上がり（motion。検知の外だが出場に必須）

- motion に **FALL 状態**を足す: `imu_attitude` の傾きが閾値（例 60°）を 0.5 s 超えたら
  歩行を止めて `FALL`、加速度の向きで前後を判定し `getup_front` / `getup_back` を自動再生、
  終わったら `HOLD`。`/motion/state` に `FALL` が出れば behavior は `SELF_DOWN` で
  受ける（README「まだ足りないもの」）。
- 起き上がりに 10 カウント。今の `getup_back` は 25 s 超（keyframe の t の和）で、
  **このままでは KO**。時間を詰めるのは技の作業で、ここでは要件として書くだけ。
- 受け入れ: 支えた状態で機体を横に倒し（トルク ON の確認を取ってから）、FALL →
  getup → HOLD が人手なしで通る。

### 2.6 段 5: 通しの模擬試合（behavior README の検証順 5〜7）

- 低い台の上で縁（転落防止の紐）。`/ring_edge` の正面ビンが台の縁と合い、EDGE で戻る。
- 箱を人が動かして SEARCH → APPROACH → ENGAGE → RETREAT を一巡。
  `/autonomy` の ON/OFF で「はじめ」「待て」「止め」を入れる。
- 全部 bag に残る（`record:=true` 既定）。**段 0 の depth bag と合わせて**、あとで
  検出の正解ラベル無し問題を追える。

## 3. 検出器のパラメータで今決めるもの

| 項目 | 今 | 変更 | 根拠 |
|---|---|---|---|
| `match.obj_width_max` | 0.60 | **0.80** | 表 2: 腕 30 cm ×2 + 胴体 |
| `match.fallen_top_max` | 0.25 | 転倒の境界 | 2026-09-23。bag のミニロボットは立位で 0.268 m。これを超えると立位が転倒に化ける |
| `match.robot_top_max` | 0.60 | 人との境界 | 同。これ以上は人・什器として棄却する。身長規定が無いので下げすぎない |
| `match.range_max` | 3.0 | 据え置き | リング対角 ≈ 3.9 m。遠方は点数不足で落ちる方が先 |
| `body.*` | 未実測 | **段 0 で実測** | 高さヒストグラムの窓中心。ここが 10 cm ずれると場外の床を掴む |
| ジャイロ | 使う | **`use_gyro` パラメータを足し、既定 true** | 「depth のみ」を厳密にしたいときは false。false のときは `plane_blend` を 0.3 → 0.7 に上げ、面法線が毎フレーム鉛直を決める。歩行時のフレーム間の傾き変化は数度で、門 12° の内側 |

ジャイロを残す理由: `/camera/imu` は motion の安定化のために常時出ている（追加コスト 0）。
外すと歩行中の面あてはめが門を外れたフレームで姿勢を運ぶ手段が無くなり、
`ATTITUDE_STALE` に落ちやすくなるだけで、得るものが無い。

## 4. ミニマムに入れないもの

- color 画像・マーカー検出（正解ラベル作りは出場後）
- 点群（検出器は使わない。rviz 用に launch 引数は残す）
- `/odom`（脚オドメトリ）。行動層は指令の積分 + 旋回モーションの実測角で持つ。
  縁は `/ring_edge`（正面のみ）と `edge_margin_slip` の余裕で守る
- 相手が 2 台以上のときの選択（最近接のまま）
- 歩行計画へのヨー追加（旋回はモーションで済ます）
- C++ 移植（Pi 5 で 33 ms に入っている。入らなくなったら `tune.stride` 3 が先）
- アルティメイトタイム・極小リングバトル（操縦で対応）

## 5. 未確定（当日か会場で確認）

## 6. 作業の依存関係

```
段0 実機で検出器 ──┬── 段1 水平前提の窓 ── 段3 定数合わせ ─┐
                  └── 段2 turn_l/r + behavior 旋回 ────┼── 段5 通し
段4 FALL + 自律起き上がり（motion。独立に進められる）───┘
```

段 0 と段 4 は今日から並行できる。段 2 は `motion_teach` でモーションを作るところが
律速で、機体を動かす作業（トルク ON の確認が要る）。
